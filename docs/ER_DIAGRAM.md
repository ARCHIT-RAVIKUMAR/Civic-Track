# Database design

```mermaid
erDiagram
    USERS ||--o{ COMPLAINTS : "reports (citizen_id)"
    COMPLAINT_CATEGORIES ||--o{ COMPLAINTS : "classifies"
    COMPLAINTS ||--o{ ASSIGNMENTS : "has"
    USERS ||--o{ ASSIGNMENTS : "works on (worker_id)"
    USERS ||--o{ ASSIGNMENTS : "assigns (assigned_by)"
    COMPLAINTS ||--o{ COMPLAINT_STATUS_HISTORY : "logs"
    USERS ||--o{ COMPLAINT_STATUS_HISTORY : "changed_by"
    COMPLAINTS ||--o| FEEDBACK : "receives"
    USERS ||--o{ FEEDBACK : "writes"

    USERS {
        uuid id PK
        varchar full_name
        varchar email UK
        varchar password_hash
        varchar role "CITIZEN|AUTHORITY|FIELD_WORKER|ADMIN"
        boolean enabled
        timestamp created_at
        timestamp updated_at
    }
    COMPLAINT_CATEGORIES {
        uuid id PK
        varchar name UK
        varchar description
        boolean active
    }
    COMPLAINTS {
        uuid id PK
        varchar title
        varchar description
        varchar location
        uuid category_id FK
        uuid citizen_id FK
        varchar status
        varchar priority
        varchar rejection_reason
        varchar image_filename
        timestamp created_at
    }
    ASSIGNMENTS {
        uuid id PK
        uuid complaint_id FK
        uuid worker_id FK
        uuid assigned_by FK
        varchar notes
        boolean active "only one active per complaint"
    }
    COMPLAINT_STATUS_HISTORY {
        uuid id PK
        uuid complaint_id FK
        varchar old_status
        varchar new_status
        uuid changed_by FK
        varchar notes
        timestamp created_at
    }
    FEEDBACK {
        uuid id PK
        uuid complaint_id FK,UK
        uuid citizen_id FK
        int rating "1..5"
        varchar comments
    }
```

Design notes
- UUID primary keys everywhere (generated by Hibernate). Enums stored as strings guarded by `CHECK` constraints.
- A partial unique index (`ux_assignments_one_active`) guarantees one active assignment per complaint; re-assignment deactivates the old row.
- History rows are append-only. Image files are stored on disk; only the generated file name is stored in the database.
